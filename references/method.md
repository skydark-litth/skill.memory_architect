# 记忆架构整理 · 方法细则

本文档补充 SKILL.md，收录实战验证过的分类标准、模板与陷阱。

## 一、诊断分类标准

### 案例 vs 规律的判别

| 形态 | 特征 | 处置 |
|------|------|------|
| 纯流水账 | 「这次做了什么、结果如何」，无普适性 | 提炼规律后压缩为 Why，或删除 |
| 带案例色彩的规律 | 规律本身有用，但 Why 里夹叙事 | 保留规律，压缩叙事为一行 Why |
| 规律 | 「遇到 X 该做 Y」 | 补齐 Why 与覆盖变体 |
| 事实/快照 | 路径、账号、版本号等 | 归入「环境事实」区，保持精简，避免写会过期的数字 |
| 元规则 | 不绑定具体问题的通用原则 | 汇总到用户级 |

### 常见结构问题（诊断时必查）

- **同族规律分散罗列**（如 3 条都源于「参数传输层吃字符」）→ 归并为一个规律族
- **同一条规则写了两遍**（如推送规则既在元规则又在项目约定）→ 去重，保留一处 + 另一处引用
- **规律缺 Why 或覆盖** → 补齐三段式
- **无元规则汇总区** → 新建
- **系统级信息误存用户级**（如数据安全红线）→ 可由系统指令承载的，判断是否仍需保留

## 二、规律格式（三段式）

```
- **<规律名>**：<遇到什么情况，该怎么做>。
  Why：<为什么会踩坑 / 证据>。
  覆盖：<还覆盖哪些变体场景>。
```

**规律族**写法：一句族规律统领，Why 里并列各变体的证据，覆盖列出全部适用场景。

示例（已验证）：

```
- **Shell 工具参数传输层会吃特殊字符**：Bash/PS 工具中含反引号、`$'...'`、双引号内反斜杠的模式一律改用 Python 读文件判断。
  Why：反引号被当命令替换吃掉（`grep -c '^```'` 实测返回 0）；`$'\r'` 退化成空模式匹配所有行；PS 转义符是反引号非反斜杠，双引号正则得 4 个字面反斜杠而误报 False。
  覆盖：统计 md 代码块、测换行符（Python `data.count(b'\r\n')`）、判路径合法性（.NET `[IO.Path]` API）。
```

## 三、元规则库（本次已建立的 14 条，可作模板）

1. 同一方法失败 2 次 = 换层（同层重试只许一次）
2. 先怀疑参数传输层，再怀疑命令逻辑
3. 破坏性动作前先判归属
4. 外部可见动作前必须获得用户明确授权
5. 判定发生在证据之后（先抓全量 → 判断 → 再排除）
6. 不确定就问，不悄悄替用户选
7. 工具不回显 stdout 时用文件中转
8. 数据安全红线：不经授权不上传第三方平台
9. 素材够用就直接用，不够才造工具
10. 同一目标连续返工 ≥3 轮 → 停止修补，固化规格清单让用户确认
11. 改时序/裁决类逻辑前，先检查会不会吃掉既有规则
12. 修 bug 先构造能复现的数据，验证先红后绿拿实测数字
13. 长期运行的服务不由 AI 工具代启，交付一键脚本
14. 瞬时/偶发类错误直接重试一次，勿纠结构造

新增元规则时，优先从项目日志里反复出现的教训中抽象。

## 四、落盘结构（用户级文件推荐模板）

```
# 用户级长期记忆
## 元规则（自动触发，不绑定具体问题）    ← 全量汇总，编号
## 本机环境事实                          ← 路径/账号/版本等快照
## 规律（规律 + Why + 覆盖）             ← 归并为规律族 + 单条规律
## 项目约定
### <项目名>                            ← 每项目一节，去重、引用元规则
```

项目级文件模板：

```
# <项目名> · 长期约定
## 核心事实（不可回退的决定）
## 易错点 / 规律
## 工具与流程
## 协作偏好（本项目）
```

## 五、任务汇报「修改过的文件明细」表模板

必须分类齐全，每类一张表，列出 **绝对路径 + 具体修改内容**：

| 类别 | 说明 |
|------|------|
| 重写 | 全文重写，逐项列出结构变化点 |
| 修订 | 外科手术式小改，逐条说明改了什么 |
| 新建 | 新文件或新目录 |
| 备份 | 备份文件的路径与来源版本 |
| 删除 | 每个文件的完整路径 + 删除理由 + 可还原性 |
| 临时文件 | 执行中自建自清的中转文件 |
| 未修改 | 明确列出「本可动但未动」的文件 |

## 六、常见陷阱（实战踩过的）

1. **`find` 的 maxdepth 太小会漏掉项目级记忆**：记忆在 `<工作区>/.workbuddy/memory/`，从工作区根算起深度为 3–4，必须 `-maxdepth 4`。
2. **回收站按卷隔离**：删除的文件进「该文件所在卷」的 `$Recycle.Bin`，不在系统盘。
3. **safe-delete 的「aborted」是误报**：报错但删除已成功，必须到回收站核实而非直接重试到报错消失。
4. **COM 读回收站被拦截**：`New-Object -ComObject Shell.Application` 会被安全策略挡下，改用 `ls` 直接列 `$Recycle.Bin`。
5. **同一文件连续编辑可能 EBUSY**：重试即可。
6. **别把「其他工作区的会话转录」当记忆**：那是工具内部数据，不在整理范围。
7. **日志超 30 天才可删**：删前必须先蒸馏其规律到 MEMORY.md，且需用户确认。
8. **写回时保留原格式**：中文文件注意编码（UTF-8 BOM 相关规则见用户级记忆），不要顺手改换行符。
9. **对外发布前必须脱敏**：技能文件 / 汇报 / README 里最易泄露的三处——①本地盘符与工作区根（如 `D:/<真实目录>`）、②真实项目名（如「某业务系统原型」）、③「本机实测输出」示例。发布前用模式集 `真实目录名|真实项目名|用户名|账号|[A-Za-z]:[\\/]` 对**整个待发布目录**复扫，命中项逐条判定「真泄露 / 通用占位写法」。已推送过敏感内容的，删文件不够——旧 commit 仍可还原，必须清空推送历史（删库重建同名空库或重写历史）。
